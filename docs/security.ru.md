# Безопасность Ingress

Этот документ для службы информационной безопасности, которая оценивает
Ingress, и для всех, кто хочет понять, что делает приложение, до установки.
Рядом с каждым утверждением стоит ссылка на файл исходного кода, где это
реализовано, так что всё можно проверить. Английская версия:
[security.md](security.md).

*Относится к Ingress 2.1.x. Дата проверки: 2026-11-12.*

## Кратко

- Ingress — это графический клиент с открытым исходным кодом (Apache-2.0) для открытых VPN-клиентов **openfortivpn** (Fortinet SSL-VPN), **openconnect** (GlobalProtect, Cisco AnyConnect) и **sstpc** (Microsoft SSTP).
- Он **не ставит фоновых служб, демонов, launch agent'ов, расширений ядра и сетевых расширений.** После выхода из приложения работают только туннели, которые вы оставили подключёнными. Они останавливаются по кнопке «Отключить».
- **Нет телеметрии, аналитики и отправки отчётов о сбоях.** Ingress соединяется только с VPN-серверами, которые вы указали, с их провайдером идентификации (IdP) во время SAML-входа и с `github.com`: оттуда он скачивает сборки VPN-клиентов и проверяет обновления. Проверку обновлений можно выключить.
- **Права root нужны только трём вещам:** процессу VPN-клиента (без root туннель не создать), установке и удалению собственных сборок VPN-клиентов и замене приложения при обновлении. Права всегда запрашиваются через штатный системный диалог администратора.
- **Пароли хранятся в системной связке ключей.** Их нет ни в файле профилей, ни в командной строке.
- Хэши sha256 скачиваемых сборок VPN-клиентов **зашиты в сам исполняемый файл Ingress**. Обновления приложения **подписаны ed25519** ключом, который никогда не покидает компьютер мейнтейнера.

## 1. Из чего состоит

| Часть | Что это | От чьего имени |
|---|---|---|
| `Ingress.app` / `ingress` | Графический интерфейс (Go + [Wails](https://wails.io), веб-интерфейс в системном WebView) | пользователь |
| `ingress --saml-login` | Отдельное окно с WebView для SAML-входа в GlobalProtect ([saml.go](../saml.go)) | пользователь |
| `ingress --pty-exec <клиент> …` | Тонкая обёртка: запускает VPN-клиент и останавливает его по «Отключить» ([ptyproxy_darwin.go](../ptyproxy_darwin.go), [elevatedwrapper_linux.go](../elevatedwrapper_linux.go)) | root |
| `openfortivpn`, `openconnect`, `sstpc` | Сами VPN-клиенты, собранные из исходников upstream в [ingress-deps](https://github.com/azizbekatajanov/ingress-deps) | root |
| `ingress --install-component` / `--remove-component` | Ставит или удаляет сборку VPN-клиента ([components_root.go](../components_root.go)) | root, разово |
| `ingress --install-update` | Заменяет приложение проверенным обновлением, только macOS ([updater_darwin.go](../updater_darwin.go)) | root, разово, и только если пользователь не может сам писать в `/Applications/Ingress.app` |

Все root-помощники — это тот же исполняемый файл, перезапущенный со скрытым флагом. Отдельных вспомогательных программ на диске нет.

## 2. Привилегии

### Как получаются права root

- **macOS:** штатный диалог администратора Security.framework (`AuthorizationExecuteWithPrivileges`), см. [elevate_darwin.go](../elevate_darwin.go). Разрешение живёт, пока запущен процесс приложения, поэтому пароль спрашивается **один раз за запуск Ingress**, а не при каждом подключении. macOS сбрасывает разрешение по своему обычному таймауту бездействия. Привилегированный помощник не устанавливается: после выхода из Ingress разрешения больше нет.
- **Linux:** `pkexec`, диалог polkit рабочего стола ([elevate_linux.go](../elevate_linux.go)). Своих правил polkit Ingress не ставит, действует политика вашей системы.
- **Windows:** не реализовано. Интерфейс работает, но «Подключить» возвращает ошибку ([elevate_windows.go](../elevate_windows.go)).

### Для чего нужен root

1. **Запуск VPN-клиента.** Создание интерфейса tun/ppp, маршрутов и DNS требует root. Клиент запускается по абсолютному пути, без поиска в `PATH` ([components.go](../components.go), `ResolvePath`).
2. **Маршруты для SSTP-профилей.** `/sbin/route` (macOS) или `ip route` (Linux) на интерфейсе туннеля, только для сетей, перечисленных в профиле ([routes_darwin.go](../routes_darwin.go), [routes_linux.go](../routes_linux.go)). `/etc/ppp/*` не трогается.
3. **Установка и удаление сборок VPN-клиентов** в каталог, принадлежащий root (раздел 4).
4. **Установка обновления**, если пользователь не может сам писать в каталог приложения (раздел 5).

Ingress не правит системные конфигурационные файлы, правила файрвола и настройки других программ. DNS и маршруты, которые присылает VPN-сервер, применяет сам VPN-клиент: `vpnc-script` у openconnect, опции `set-dns`/`set-routes` у openfortivpn (настраиваются в профиле).

## 3. Сетевые соединения

| Куда | Кто соединяется | Когда | Зачем |
|---|---|---|---|
| VPN-шлюз / портал из профиля | VPN-клиент (root); сам Ingress — для prelogin GlobalProtect | При подключении | Само VPN-соединение |
| Ваш провайдер идентификации (IdP) | WebView `ingress --saml-login` | SAML-вход GlobalProtect | Вы входите на странице самого IdP |
| `github.com/azizbekatajanov/ingress-deps/releases/download/…` | Ingress | Первое подключение профиля данного типа или «Установить/Обновить» на экране «Компоненты» | Скачать сборку VPN-клиента |
| `github.com/azizbekatajanov/ingress/releases/latest/download/ingress-update.json` (+ `.sig`) | Ingress | Через 5 с после запуска, затем раз в 24 ч. **Выключается в «О программе».** | Проверить обновление |
| `github.com/azizbekatajanov/ingress/releases/download/…` | Ingress | Только после нажатия «Обновить» | Скачать обновление |

GitHub отдаёт файлы релизов через редирект на свой CDN (`objects.githubusercontent.com` / `release-assets.githubusercontent.com`). Если вы фильтруете исходящий трафик, разрешите эти хосты.

Больше никуда. Нет аналитики, отчётов об ошибках, проверок лицензии и прочих «звонков домой». Интерфейс встроен в исполняемый файл и ничего не грузит из интернета ([main.go](../main.go), `//go:embed all:frontend/dist`).

**TLS:** скачивание идёт только по `https`, всё остальное отклоняется ([components.go](../components.go), `downloadVerified`). Prelogin GlobalProtect проверяет сертификат сервера по системным корневым сертификатам, по CA-файлу из профиля или по закреплённому ключу ([gp_prelogin.go](../gp_prelogin.go)). Опции профиля «insecure SSL» / «не проверять» (Fortinet, SSTP) нужны для тестовых серверов и по умолчанию выключены.

## 4. Что хранится на диске

| Что | Где | Защита |
|---|---|---|
| Профили (серверы, логины, опции; **без паролей**) | `~/Library/Application Support/ingress/profiles.json` (macOS), `~/.config/ingress/` (Linux) | Каталог 0700, файл 0600 ([profile.go](../profile.go)) |
| Сохранённые пароли | Системная связка ключей, сервис `ingress` | Keychain / Secret Service ([credentials.go](../credentials.go)) |
| Конфиг подключения Fortinet (с паролем) | Временный файл во временном каталоге пользователя, пока работает туннель | 0600, удаляется при отключении ([openfortivpn_config.go](../openfortivpn_config.go)). Так пароль не попадает в аргументы процесса, где его через `ps` видели бы другие пользователи. |
| Веб-сессия SAML (cookie IdP) | macOS: стандартное хранилище WebKit приложения Ingress; Linux: `~/.local/share/ingress/saml-cookies.sqlite` | Чтобы не входить в IdP каждый раз ([saml_darwin.m](../saml_darwin.m), [saml_linux.c](../saml_linux.c)). Prelogin-cookie GlobalProtect, который возвращает SAML, передаётся openconnect и нигде не сохраняется. |
| Сборки VPN-клиентов | `/Library/Application Support/Ingress/components/` (macOS), `/opt/ingress/components/` (Linux) | Владелец root, 0755, запись для группы и остальных запрещена |
| Журналы подключений | **Только в памяти**, показываются на вкладке «Журнал» | Секреты, переданные клиенту через stdin, маскируются ([vpn_manager.go](../vpn_manager.go)) |

Пароли и SAML-cookie передаются VPN-клиенту через **stdin** (`--passwd-on-stdin`, `--password -`), а не через аргументы командной строки.

## 5. Цепочка поставки: что скачивается и как проверяется

### Сборки VPN-клиентов (ingress-deps)

- Собираются из **релизных тегов upstream** (openconnect 9.21, openfortivpn 1.20.5, sstp-client 1.0.20) с патчами из [ingress-deps/patches](https://github.com/azizbekatajanov/ingress-deps/tree/main/patches). В каждом архиве есть `LICENSES/` и `SOURCES.txt`.
- Какие патчи применяются (все небольшие и публичные):
  - openconnect `0001`: отправлять пустой `passwd` рядом с SAML-cookie (нужно некоторым шлюзам GlobalProtect; upstream MR !656).
  - openconnect `0002`: включить `SSL_OP_LEGACY_SERVER_CONNECT`, чтобы подключаться к старым шлюзам PAN-OS без RFC 5746. Само небезопасное пересогласование остаётся запрещённым, список шифров и уровень безопасности не меняются.
  - sstp-client `0001`: читать пароль из stdin, а не из аргументов.
  - sstp-client `0002`: исправление переполнения стека в массиве аргументов pppd.
- URL и **sha256 каждой сборки зашиты в исполняемый файл Ingress** ([components_manifest.go](../components_manifest.go)). Новая версия клиента выходит только вместе с новым релизом Ingress.
- Как идёт установка ([components_root.go](../components_root.go)):
  1. Архив скачивается по https, sha256 проверяется без привилегий.
  2. Root-установщик **читает архив в память, заново считает sha256 и сверяет со своим встроенным манифестом**, а распаковывает те же самые байты. Подменить файл между проверкой и использованием нельзя.
  3. Распаковка принимает только обычные файлы и каталоги: никаких симлинков, жёстких ссылок, устройств и путей с `..`, не больше 300 МБ в распакованном виде. Файлы собираются во временном каталоге и подменяются атомарно.
  4. Всё переводится во владение root и закрывается от записи для группы и остальных.
- **Перед каждым подключением** проверяется вся цепочка каталогов до исполняемого файла: нет симлинков, владелец root, запись для группы и остальных запрещена ([components_secure_unix.go](../components_secure_unix.go)). Если проверка не прошла, файл не запускается.

### Обновления приложения (macOS)

- В каждом релизе есть `ingress-update.json` (версия, URL архива, sha256) и его **подпись ed25519**. Закрытый ключ хранится офлайн в связке ключей мейнтейнера, не на GitHub ([updater.go](../updater.go), [tools/updatesign](../tools/updatesign)). **Даже со взломанного GitHub-аккаунта нельзя выпустить обновление, которое Ingress примет.**
- Без нажатия «Обновить» ничего не устанавливается.
- Новый бандл должен совпадать по версии с подписанным манифестом и проходить `codesign --verify --deep --strict`. Если нужен root, root-сторона **сама ещё раз проверяет подпись и хэш** по копии в `/var/root`.

### Подпись кода: как есть сейчас

| Платформа | Сейчас | В планах |
|---|---|---|
| macOS | Ad-hoc подпись, **без нотаризации** (нет Apple Developer ID). При первом запуске из `.dmg` Gatekeeper показывает предупреждение. Собирается на Mac мейнтейнера. | Сборка в CI с SLSA-аттестацией (раздел 6) |
| Windows | Не подписан (и VPN-подключения там пока не работают) | Authenticode через SignPath Foundation |
| Linux | `.sha256` рядом с каждым файлом | SLSA-аттестация |

## 6. Как проверить то, что вы ставите

**Контрольная сумма.** Рядом с файлами для Linux и Windows лежит `.sha256`:

```bash
sha256sum -c Ingress-2.1.0-linux-amd64.deb.sha256
```

Для macOS sha256 каждого архива приложения (`Ingress-<версия>-darwin-<arch>.zip`) записан в подписанном `ingress-update.json` того же релиза:

```bash
shasum -a 256 Ingress-2.1.0-darwin-arm64.zip
plutil -extract 'assets.darwin/arm64.sha256' raw -o - ingress-update.json
```

Для `.dmg` контрольная сумма пока не публикуется. Используйте `.zip` или `install.sh`, который проверяет её сам.

**Целостность подписи на macOS:**

```bash
codesign --verify --deep --strict --verbose=2 /Applications/Ingress.app
```

**`install.sh`**: прочитайте его перед запуском ([install.sh](../install.sh), около 60 строк). Он скачивает манифест обновлений, принимает только URL из релизов этого репозитория, проверяет sha256 и подпись кода и копирует приложение в `/Applications`. Файл, скачанный через `curl`, не получает атрибут карантина, поэтому Gatekeeper не показывает предупреждение. Этот способ установки существует только ради этого, а проверки выше заменяют те, что сделал бы Gatekeeper. Можно и вручную: скачать `.zip`/`.dmg`, проверить, как показано выше, и открыть.

**Происхождение сборки** *(в планах, после переноса сборки релизов в CI)*:

```bash
gh attestation verify Ingress-<версия>-darwin-arm64.zip --repo azizbekatajanov/ingress
```

Это доказывает, что файл собран workflow GitHub Actions этого репозитория из конкретного коммита.

**Собрать самому:** весь код открыт. См. раздел *Building* в README и скрипты сборки в ingress-deps.

## 7. Модель угроз

**От чего Ingress защищает:**

- подмена скачанной сборки VPN-клиента или обновления (sha256 зашит в исполняемый файл; обновления подписаны ed25519; root-сторона проверяет всё заново);
- выпуск вредоносного обновления со взломанного GitHub-аккаунта (без офлайн-ключа не получится);
- подмена исполняемого файла, который запускается под root, локальным процессом без прав администратора. Перед каждым запуском сам файл и все каталоги над ним, вплоть до `/`, должны принадлежать root и быть закрыты от записи для группы и остальных. Это касается собственных сборок Ingress, своих путей с экрана «Компоненты» и бинарников, найденных в `PATH`. Симлинки сначала разрешаются, и запускается именно найденный файл. Root-обёртка повторяет проверку перед запуском клиента ([components_secure_unix.go](../components_secure_unix.go), `trustedExecPath`). Поэтому Homebrew-бинарник из `/opt/homebrew/bin` (каталог принадлежит пользователю) отклоняется, и Ingress предлагает свою сборку;
- чтение VPN-паролей другими локальными пользователями (связка ключей; stdin или файл 0600 вместо аргументов);
- вредоносные архивы (выход за пределы каталога, симлинки, zip-бомбы).

**От чего Ingress не защищает — это важно знать:**

- **Библиотеки своих и системных бинарников.** Проверка владельца касается самого исполняемого файла, но не разделяемых библиотек, которые он загружает. Собственные сборки Ingress собраны со статическим OpenSSL. Если же сторонний бинарник принадлежит root, но грузит библиотеки из места, доступного пользователю на запись, это вне проверки. **Рекомендация для управляемых парков: используйте только собственные сборки Ingress и не задавайте своих путей.**
- **Кэшированное разрешение администратора на macOS.** После первого запроса пароля запущенный процесс Ingress может запускать root-помощники без повторного запроса, пока macOS не сбросит разрешение. Код, оказавшийся в этот момент внутри процесса Ingress, получит то же самое.
- Злоумышленник, у которого уже есть права администратора или контроль над вашей учётной записью.
- Вредоносный или скомпрометированный VPN-шлюз: он может прислать маршруты и DNS, как и любому другому VPN-клиенту.
- Уязвимости в openconnect, openfortivpn, sstp-client, pppd, OpenSSL и системном WebView. Мы следим за релизами upstream и выпускаем пересобранные клиенты.

## 8. Сравнение с официальными клиентами вендоров

Ingress подключается к тем же шлюзам через открытые реализации протоколов, но **не заменяет** агент управления конечными устройствами. Проверьте, разрешает ли это ваша политика:

| Возможность | FortiClient / GlobalProtect / Secure Client | Ingress |
|---|---|---|
| Fortinet EMS / ZTNA posture, телеметрия устройства | Да | **Нет** |
| HIP-отчёт GlobalProtect | Реальное состояние устройства | **Опционально, по умолчанию выключен.** Если включить, его формирует `hipreport.sh` из openconnect, который **не проверяет устройство**: он сообщает фиксированные значения. Не считайте его подтверждением состояния устройства. |
| Cisco hostscan / CSD, Cisco SAML | Да | **Нет** (Ingress прямо об этом сообщает, а не падает молча) |
| Always-on / pre-logon VPN, принудительный запрет split tunnel | По политике | Нет. Пользователь сам подключается и отключается. Маршруты — те, что присылает сервер или указаны в профиле. |
| Несколько туннелей одновременно | Нет | **Да**, ради этого Ingress и сделан. С одной машины могут быть одновременно доступны несколько корпоративных сетей; допустимо ли это — решение вашей политики. |
| Фоновая служба / расширение ядра | Да | Нет |
| Исходный код | Закрыт | Открыт (Apache-2.0); VPN-клиенты под LGPL/GPL |

## 9. Что планируется усилить

- Собирать каждый релиз (включая macOS) в GitHub Actions с **SLSA-аттестацией происхождения** и **SBOM** — и для Ingress, и для ingress-deps.
- **Подпись Authenticode** для Windows-сборок через SignPath Foundation.
- Автоматическая **проверка на VirusTotal** каждого файла релиза со ссылкой на отчёт в описании релиза.
- **CodeQL, govulncheck, gosec и OpenSSF Scorecard** в CI.

Как сообщить об уязвимости: [SECURITY.md](../SECURITY.md).
